# 実装レビュー観点

## 仕様整合

- 要件・基本設計・受入条件に対応しているか。
- 仕様外の振る舞いを追加していないか。
- エラー時、権限不足時、0件時、重複時などの境界条件を扱っているか。

## コード品質

- 既存の責務分割、命名、配置、型、エラーハンドリングに合っているか。
- 共有部品の変更が呼び出し元に影響していないか。
- 重複を増やしすぎていないか。
- 不要な依存や設定を追加していないか。

## データ・互換性

- DB変更にマイグレーション、初期値、ロールバック観点があるか。
- 既存データが壊れないか。
- APIレスポンス、イベント、ファイル形式などの互換性を壊していないか。

## セキュリティ

- 認証・認可チェックが適切か。
- ユーザー入力の検証、エスケープ、サニタイズがあるか。
- 秘密情報をログやフロントエンドに出していないか。
- 監査ログが必要な操作で記録されるか。

## 運用

- ログ、メトリクス、アラート、リトライ、タイムアウトが既存方針に合っているか。
- 障害時の切り分けに必要な情報が残るか。
- バッチや外部IFは再実行・冪等性を考慮しているか。
