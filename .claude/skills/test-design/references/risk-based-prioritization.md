# リスクベース優先度

## 優先度

| 優先度 | 意味 |
|---|---|
| Must | リリース/検収に必須。失敗時の業務影響が大きい |
| Should | 重要。代替確認や後続対応は可能 |
| Could | 余力があれば確認 |

## リスク評価軸

| 軸 | 高リスクの例 |
|---|---|
| 業務影響 | 売上、請求、契約、顧客通知、運用停止 |
| データ影響 | 削除、上書き、重複、整合性破壊 |
| セキュリティ | 権限、個人情報、監査、外部公開 |
| 外部依存 | 外部IF、決済、メール、ファイル連携 |
| 変更規模 | 共通部品、DBスキーマ、認証基盤 |
| 発生頻度 | 毎日使う、ピーク時に集中する |
| 検知困難性 | 失敗がログに残らない、利用者が気づきにくい |

## 自動化判断

自動化優先:

- 頻繁に実行する回帰観点
- 権限、入力検証、API、Service、DB整合性
- バッチの正常/異常/再実行
- 外部IFの契約テスト

手動でもよい:

- 一度だけの移行確認
- 見た目の最終確認
- 顧客確認が必要な文言や業務判断
- 外部環境依存が強く自動化コストが高いもの
