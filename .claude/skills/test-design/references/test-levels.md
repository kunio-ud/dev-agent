# テストレベル定義

## テストレベル

| レベル | 目的 | 主な対象 |
|---|---|---|
| 単体 | 小さな関数/Serviceのロジック確認 | 純粋関数、Service、validation |
| 結合 | 複数部品の接続確認 | API+Service+Repository+DB、外部IF stub |
| システム | 業務フロー全体の確認 | 画面/API/DB/バッチ/権限/監査 |
| 受入 | 顧客合意・検収条件の確認 | AC、業務シナリオ、UAT |
| 性能 | NFRの性能条件確認 | 応答時間、バッチ時間、負荷 |
| セキュリティ | 権限・情報保護の確認 | 認証認可、監査、入力攻撃 |

## 割り当て方

- 純粋な計算、変換、業務判断は単体テスト。
- DBやRepositoryを含む処理は結合テスト。
- 画面からDB更新まで通す業務フローはシステムテスト。
- 顧客の受入条件は受入テスト。
- NFRは通常の機能テストに混ぜず、性能/セキュリティ/運用観点として分ける。

## 重複を避ける

- すべてをE2Eで確認しない。
- 単体で十分なロジックは単体に寄せる。
- DB制約やトランザクションは結合で確認する。
- 受入テストは代表シナリオに絞る。
