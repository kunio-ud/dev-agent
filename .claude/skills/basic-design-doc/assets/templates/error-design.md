# エラー設計テンプレート

## 1. エラー設計方針

本システムにおけるエラーの分類体系・コード採番規則・処理方針を定義する。

### 1.1 エラー分類

| 分類 | 定義 | HTTPステータス例 | 対処主体 |
|------|------|----------------|---------|
| 業務エラー | ユーザー操作・業務ルール違反に起因するエラー | 400, 409, 422 | ユーザー |
| 認証・認可エラー | 認証失敗・権限不足 | 401, 403 | ユーザー／管理者 |
| リソースエラー | 対象データが存在しない／競合 | 404, 409 | ユーザー |
| システムエラー | プログラム不具合・想定外状態 | 500 | 運用チーム |
| 外部システム連携エラー | 連携先の障害・タイムアウト | 502, 503, 504 | 運用チーム |
| インフラエラー | DB・ネットワーク・ストレージ障害 | 500, 503 | インフラチーム |

### 1.2 エラーコード採番規則

形式: `ERR-{モジュール}-{連番3桁}`

| 例 | 意味 |
|----|------|
| `ERR-AUTH-001` | 認証モジュールの 1 番目のエラー |
| `ERR-JE-005` | 仕訳モジュールの 5 番目のエラー |
| `ERR-SYS-001` | システム共通エラー |

- モジュール略号は [api-interface.md](./api-interface.md) のAPI-IDモジュールと揃える
- 共通エラー（バリデーション失敗等）は `ERR-CMN-XXX`、未分類のシステムエラーは `ERR-SYS-XXX`

## 2. エラーコード定義表

| エラーID | エラー名 | 分類 | HTTPステータス | 業務影響 | ユーザー向けメッセージ | 内部メッセージ／調査ポイント | 対応API | 復旧方法 |
|---------|---------|------|--------------|---------|---------------------|------------------------|---------|---------|
| ERR-CMN-001 | 必須項目未入力 | 業務 | 400 | 低 | 「{項目名}を入力してください」 | バリデーション失敗。入力値ログを確認 | 全API | ユーザー再入力 |
| ERR-CMN-002 | 入力値形式エラー | 業務 | 400 | 低 | 「{項目名}の形式が正しくありません」 | フォーマット違反。期待形式と入力値を比較 | 全API | ユーザー再入力 |
| ERR-AUTH-001 | 認証失敗 | 認証 | 401 | 中 | 「メールアドレスまたはパスワードが正しくありません」 | アカウント存在／パスワードハッシュ比較失敗 | API-001 | 再ログイン |
| ERR-AUTH-002 | アカウントロック | 認証 | 403 | 中 | 「アカウントがロックされています。30分後に再試行してください」 | 連続失敗5回でロック発動 | API-001 | 待機 or 管理者解除 |
| ERR-AUTH-003 | トークン期限切れ | 認証 | 401 | 低 | 「セッションの有効期限が切れました。再ログインしてください」 | JWT exp 検証失敗 | 全認証API | 再ログイン |
| ERR-AUTH-004 | 権限不足 | 認可 | 403 | 中 | 「この操作を実行する権限がありません」 | RBAC ロール不一致 | 全API | 管理者へ依頼 |
| ERR-RES-001 | データ未存在 | リソース | 404 | 低 | 「対象のデータが見つかりません」 | 主キー検索結果0件。論理削除も確認 | GET系API | 一覧再取得 |
| ERR-RES-002 | 楽観ロック競合 | リソース | 409 | 中 | 「他のユーザーが更新しました。最新データで再操作してください」 | version カラム不一致 | 更新系API | 再取得→再操作 |
| ERR-SYS-001 | システム内部エラー | システム | 500 | 高 | 「システムエラーが発生しました。時間をおいて再試行してください」 | スタックトレース・相関ID（traceId）から調査 | 全API | 自動復旧／運用調査 |
| ERR-EXT-001 | 外部システムタイムアウト | 連携 | 504 | 高 | 「処理がタイムアウトしました。時間をおいて再試行してください」 | 連携先レスポンス10秒超過。連携先のヘルスチェック | 連携API | リトライ／代替手段 |
| ERR-INF-001 | DB接続エラー | インフラ | 503 | 致命 | 「現在サービスをご利用いただけません」 | コネクションプール枯渇／DBダウン | 全API | インフラチーム対応 |

> **記載順は HTTPステータス昇順 → モジュール別** とすること。

## 3. エラーレスポンス共通フォーマット

すべてのAPIエラーレスポンスは下記フォーマットに従う（[api-interface.md](./api-interface.md) の「共通仕様」と同一）。

```json
{
  "error": {
    "code": "ERR-AUTH-001",
    "message": "メールアドレスまたはパスワードが正しくありません",
    "trace_id": "abc123def456",
    "details": [
      { "field": "email", "message": "形式が正しくありません" }
    ]
  }
}
```

| フィールド | 必須 | 内容 |
|----------|------|------|
| `code` | ○ | 本書のエラーID |
| `message` | ○ | ユーザー向けメッセージ |
| `trace_id` | ○ | ログ追跡用の相関ID（リクエスト単位で発行） |
| `details` | - | フィールド単位のバリデーションエラー（複数可） |

## 4. 例外処理方針

### 4.1 階層別ハンドリング

| 階層 | 責務 | 漏れた場合の挙動 |
|------|------|----------------|
| バリデーション層 | 入力値検証、ERR-CMN-XXX を返す | コントローラ層へ委譲 |
| ビジネスロジック層 | 業務エラーを ERR-{業務}-XXX として throw | コントローラ層で 500 に集約 |
| データアクセス層 | DB例外を ERR-INF-XXX または ERR-RES-XXX に変換 | システムエラーとして 500 |
| グローバルハンドラ | 未補足例外を ERR-SYS-001 として返す＋アラート発火 | （最終防衛線） |

### 4.2 リトライ方針

| エラー種別 | リトライ可否 | 回数／間隔 | 対象API |
|----------|------------|-----------|---------|
| ERR-EXT-001 タイムアウト | ○ | 最大3回／指数バックオフ（1s, 2s, 4s） | 外部連携API |
| ERR-INF-001 DB接続 | ○ | 最大2回／500ms間隔 | 全API |
| ERR-RES-002 楽観ロック競合 | ✕（ユーザー判断） | - | 更新系API |
| ERR-AUTH-* 認証エラー | ✕ | - | 全API |
| ERR-CMN-* バリデーション | ✕ | - | 全API |

### 4.3 フォールバック方針

- **キャッシュフォールバック**: 参照系APIで連携先障害時は最終正常データ（最大1時間以内）を返却し、レスポンスヘッダ `X-From-Cache: true` を付与
- **サーキットブレーカー**: 連携先で 30 秒以内に 5 回連続失敗した場合、以降1分間は即座に `ERR-EXT-001` を返却（連携先の更なる悪化を防止）
- **代替手段の明示**: 機能停止時、ユーザーに代替手段（電話・メール窓口）を画面に表示

## 5. ログ出力規則

エラー発生時、以下を構造化ログ（JSON）として出力する。

| フィールド | 説明 | 例 |
|----------|------|-----|
| `timestamp` | ISO 8601 (UTC) | `2026-04-30T12:34:56Z` |
| `level` | DEBUG / INFO / WARN / ERROR / FATAL | `ERROR` |
| `error_code` | エラーID | `ERR-AUTH-001` |
| `trace_id` | 相関ID | `abc123def456` |
| `user_id` | ログイン中のユーザーID（取得可能なら） | `42` |
| `request_path` | エンドポイント | `POST /v1/auth/login` |
| `request_id` | リクエストUUID | `uuid-...` |
| `message` | エラー内容（内部用） | `Password mismatch for user_id=42` |
| `stack_trace` | スタックトレース（ERROR以上） | `...` |

**マスキングルール**：
- パスワード・トークン・クレジットカード番号・マイナンバー等の機微情報はログに出さない
- 個人情報（メール・氏名・電話）はマスキング（例: `t***@example.com`）

## 6. アラート方針

| エラーレベル | 通知先 | 通知タイミング | 通知手段 |
|------------|--------|--------------|---------|
| FATAL（ERR-INF-*） | 運用チーム＋オンコール | 即時 | PagerDuty + Slack |
| ERROR（ERR-SYS-*） | 運用チーム | 5分間に10件超で発火 | Slack |
| ERROR（ERR-EXT-*） | 運用チーム | 5分間に20件超で発火 | Slack |
| WARN（業務エラー集中） | プロダクトチーム | 1時間に同一コード100件超 | Slack |
