# 要件定義 品質基準

## 要件ID規則

推奨ID:

**要件フェーズID（要件定義書内で使用）**

| 種別 | ID例 | 用途 |
|---|---|---|
| 成功基準 | `KPI-001` | 目標達成を測定する指標（2章で使用） |
| 業務課題 | `ISS-001` | 現行業務・システムの課題（3章で使用） |
| 業務要件 | `BR-001` | 業務上達成すべきこと |
| 機能要件 | `FR-001` | システムが提供する機能 |
| 画面要件 | `SCRR-001` | 画面単位の要件（要件フェーズ）|
| 帳票要件 | `RPT-001` | 帳票・出力物の要件 |
| 通知要件 | `NTF-001` | 通知・アラートの要件 |
| バッチ要件 | `BAT-001` | バッチ・データ処理の要件 |
| 非機能要件 | `NFR-{分類}-001` | 性能・可用性・セキュリティなど（例: `NFR-PERF-001`）|
| データ要件 | `DR-001` | 主要データ、保持、移行、品質 |
| データ移行要件 | `DR-MIG-001` | 移行対象データ固有の要件 |
| 外部連携要件 | `IR-001` | 外部システム連携 |
| 移行要件 | `MIG-001` | システム・データ移行の要件 |
| 導入要件 | `IMP-001` | 導入・教育・切替条件 |
| テスト要件 | `TST-001` | テスト種別・条件 |
| 受入条件 | `AC-001` | 受入基準・判定条件 |
| 制約 | `CON-001` | 技術・契約・運用・法令などの制約 |
| 未決事項 | `TBD-001` | 確認が必要な事項 |
| リスク | `RSK-001` | 実現性・スケジュール・品質などのリスク |

**基本設計フェーズIDとの対応（トレーサビリティ用）**

| 要件フェーズID | 対応する基本設計フェーズID | 備考 |
|---|---|---|
| `SCRR-001` | `SCR-001` | 要件→画面設計 |
| `RPT-001` | `RPTD-001` | 要件→帳票設計 |
| `NTF-001` | `NTF-001`（通知仕様書）| 要件→通知設計（プロジェクト次第） |
| `FR-001` | `API-001` | 要件→API設計 |
| `DR-001` | `TBL-001` | 要件→テーブル設計 |
| `BAT-001` | `FLOW-001` | 要件→処理フロー設計 |
| `IR-001` | `IF-001`（IF仕様書）| 要件→IF設計（プロジェクト次第） |

既存プロジェクトのID体系がある場合は、それを優先する。

## 要件の粒度

良い要件:

- 利用者または業務主体が明確。
- 達成したい結果が明確。
- 条件、例外、頻度、対象データが必要に応じて書かれている。
- 受入条件で判定できる。

悪い要件:

- 「使いやすくする」「高速化する」など測定できない。
- 複数の要求が1行に混ざっている。
- 実装方式だけが書かれていて、業務目的が不明。
- 誰の要求か、どの課題に対応するか不明。

## 優先度

推奨区分:

| 優先度 | 意味 |
|---|---|
| Must | リリース・検収に必須 |
| Should | 重要だが代替運用または後続対応が可能 |
| Could | 余力があれば対応 |
| Won't | 今回対象外として明示 |

優先度は顧客価値、法令・契約、業務停止影響、代替運用可否で判断する。

## 受入条件

各要件に最低1つの受入条件を付ける。

書式例:

- 前提: 対象ユーザーがログイン済みである。
- 操作/条件: 対象期間を指定して検索する。
- 期待結果: 条件に一致するデータのみが一覧表示される。
- 判定基準: 5秒以内に初期表示され、0件時は空結果メッセージを表示する。

## トレーサビリティ

基本の対応:

```
BR-001 業務上の課題・目的
  -> FR-001 機能要件
  -> NFR-PERF-001 性能要件
  -> 基本設計: SCR-001 / API-001 / TBL-001
  -> テスト: UT-001 / ST-001 / UAT-001
```

要件定義段階では、基本設計以降のIDが未確定でも「画面候補」「API候補」「データ候補」として残す。

## 曖昧語の扱い

曖昧語はそのまま確定要件にしない。

| 曖昧語 | 置き換え例 |
|---|---|
| 高速 | 通常時95パーセンタイルで3秒以内 |
| 大量 | 1日100万件、ピーク時1時間10万件 |
| 安全 | 管理者権限操作は監査ログを保存し、90日保持 |
| 使いやすい | 主要操作は3クリック以内、入力必須項目を明示 |
| 随時 | 営業時間中は15分ごと、夜間は1時間ごと |

数値が決められない場合は暫定値、根拠、確認先を記載する。
